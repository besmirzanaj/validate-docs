## `webapp` — Web Application Scan

Tools and what they check:

| Tool | What it checks |
|------|----------------|
| **nuclei** | Known vulnerabilities (CVE-based templates, critical/ high/ medium severity) |
| **nikto** | Web server misconfigurations, outdated software, dangerous files |
| **whatweb** | Technology fingerprint (CMS, web server, frameworks, analytics) |
| **dirsearch** | Hidden paths, backup files, exposed directories |
| **sqlmap** | SQL injection detection (light level) |

Best for: auditing your own web applications, checking for OWASP Top 10 issues.

## `dns-audit` — DNS Audit Scan

A full DNS zone audit, not just a records lookup. Tools and what they check:

| Tool | What it checks |
|------|----------------|
| **dig** | A, AAAA, CNAME, SOA, NS, MX and TXT records; SPF/DMARC/DKIM policy grading; SOA timers; SOA and NS-recordset consistency across every nameserver; AXFR (zone transfer); the DNSSEC chain (DNSKEY, DS, the resolver's AD bit); CHAOS `version.bind` leaks; NS IPv6 coverage; PTR records per nameserver; parent/child delegation and glue consistency; open-resolver behaviour |
| **whois** | Geographic/ASN diversity of the nameservers (one lookup per NS IP) |
| **crt.sh** | Passive subdomain enumeration from certificate transparency logs (no brute force), capped at 200 names |
| **curl** | HTTP response headers |

The summary states whether the domain has MX records, an SPF record and a DMARC record, for example `SPF: missing`.

### Markdown report

`GET /scans/{id}/report.md` renders a narrative audit report — a score per category (NS delegation, SOA replication, DNSSEC, AXFR security, IPv6 readiness, geographic diversity, CHAOS security) plus a short written "Bottom Line". The scores are computed deterministically from the scan's own facts; only the Bottom Line paragraph is LLM-written. Available on every plan, for `dns-audit` scans only. Like the JSON report, it renders lazily: the first request returns `202` while it generates, a later request returns the file.

## `ip` — Network Scan

Tools and what they check:

| Tool | What it checks |
|------|----------------|
| **nmap** | Every TCP port, with service and OS detection on the open ones |

Takes about two minutes. The summary lists the open ports with their services, for example `Open ports (3): 53/tcp domain; 80/tcp http; 443/tcp ssl/http`.

Best for: discovering exposed services and unauthorized open ports.
